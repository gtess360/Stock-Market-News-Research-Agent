## 1. Executive Summary

Phase 3.7 implements the persistence, retrieval, keyword search, multi-field filtering, session restoration (reopening), and multi-format export capabilities for the Stock Market News Research Agent.

All research executions, synthesized summaries, corporate developments, forward-looking sentiment outlooks, transparent catalyst weights, downside risks, and verified source citations are immutably persisted in SQLite. Users can review, filter, and inspect past reports scoped strictly to their authenticated account. Any saved report can be reopened into the active dashboard workspace without triggering redundant LangGraph agent executions or deducting user credits. Furthermore, users can export reports in four formats: **Markdown (.md)**, **JSON (.json)**, **CSV (.csv)**, and **PDF (.pdf)** with pure-Python rendering.

## 2. Technical Architecture & Component Design

The research history and export system is organized into modular services with strict separation of concerns:

```
src/
├── services/
│   ├── history_service.py     # Scoped SQL queries, multi-criteria filters, keyword search, pagination
│   └── export_service.py      # Markdown, JSON, CSV, and PDF report formatters
├── ui/
│   └── history_view.py        # Streamlit UI: search inputs, filter widgets, paginated report cards, exports
└── agent/
    └── nodes.py               # Persists research reports idempotently into SQLite
```

### 2.1 Database Persistence Architecture
Research jobs, source records, and synthesized reports are linked through strict relational foreign keys:
- **`research_jobs`**: Stores execution metadata (`id`, `user_id`, `tab`, `ticker_list_json`, `start_at`, `end_at`, `horizon_days`, `status`, `credit_debited`, `created_at`).
- **`research_reports`**: Stores full structured outputs (`report_json`), pre-rendered markdown (`markdown`), prompt version (`prompt_version`), and model metadata (`model_version`).
- **`source_records`**: Stores raw point-in-time retrieved articles, publisher names, URLs, timestamps, and deduplication flags.

In `src/agent/nodes.py`, report persistence uses `INSERT OR REPLACE INTO research_reports` to guarantee idempotency across duplicate job retries.

## 3. Strict User Ownership Isolation

To eliminate cross-tenant data leakage and prevent unauthorized report access:
1. **Server-Side User Scoping:** Every SQL query generated by `history_service.py` explicitly enforces `WHERE j.user_id = ?` using parameterized queries.
2. **Access Control on Detail Retrieval:** `get_user_job_detail(user_id, job_id)` includes `WHERE j.id = ? AND j.user_id = ?`. If a user attempts to request another user's job ID, the query returns `None`, rejecting unauthorized access.
3. **Audit Integrity:** Reopening or viewing past reports does not touch or leak access tokens, password hashes, or session credentials.

---

## 4. Search, Filtering & Pagination Engine

`query_user_research_history()` provides server-side filtering with dynamic parameter binding:
- **Ticker Symbol Filtering:** Matches specific tickers inside JSON arrays (`j.ticker_list_json LIKE '%"AAPL"%'`).
- **Date Range Windows:** Filters reports by historical bounds (`j.start_at >= ?` and `j.end_at <= ?`).
- **Research Mode (Tab):** Isolates `news` vs `sentiment` research runs.
- **Completion Status:** Filters between `completed` and `failed` jobs.
- **Full Keyword Search:** Performs case-insensitive matching across:
  - Synthesized Executive Summaries and Findings (`COALESCE(r.report_json, '') LIKE ?`)
  - Full Markdown Text (`COALESCE(r.markdown, '') LIKE ?`)
  - Target Tickers (`j.ticker_list_json LIKE ?`)
- **Server-Side Pagination:** Supports customizable page sizes (5, 10, 20) with `LIMIT ? OFFSET ?` and total record counting for responsive navigation.

---

## 5. Idempotent Dashboard Reopening (Zero-Debit Policy)

Users can click **"📂 Reopen in Dashboard"** on any past completed report:
1. The historical state (`selected_tickers`, `start_date`, `end_date`, `horizon_days`, and synthesized payload) is restored directly into `st.session_state`.
2. The active research cache (`st.session_state["research_results"][cache_key]`) is populated from the persisted database report.
3. The dashboard UI switches active views, immediately displaying the full report, interactive Plotly charts, timelines, and sentiment workbench.
4. **Zero-Quota Debit:** No new research job is created, no LLM API calls are made, and zero user credits are deducted.

## 6. Multi-Format Export Specifications

Users can export reports from either the History view or directly from active dashboard tabs.

### 6.1 Publication-Grade Markdown (`.md`)
- Complete header with generation timestamps (UTC), target tickers, and date window.
- Executive summary, corporate news developments, and scenario outlooks.
- Formatted markdown tables for verified source citations (`| Article ID | Publisher | Date | Verified Claim | Source Link |`).
- Standard regulatory and methodology compliance disclaimers.

### 6.2 Structured JSON (`.json`)
- Clean machine-readable JSON schema containing:
  - `job_id`, `user_id`, `tab`, `tickers`, `date_range`, `forward_horizon_days`
  - `status`, `created_at`, `completed_at`, `model_version`
  - `report` (structured executive summary, news summaries, sentiment outlooks, citations)
  - `source_records` (raw point-in-time articles)
  - `disclaimer`

### 6.3 Tabular CSV (`.csv`)
- Multi-section CSV suitable for Excel, Pandas, or institutional quantitative pipelines.
- Standardized columns: `Record Type`, `Ticker`, `Category`, `Date`, `Publisher`, `Claim / Headline / Summary`, `Source URL`, `Notes / Weights`.
- Contains rows for:
  - `EXECUTIVE_SUMMARY`
  - `KEY_DEVELOPMENT`
  - `SENTIMENT_OUTLOOK`
  - `CATALYST`
  - `DOWNSIDE_RISK`
  - `OPPOSING_EVIDENCE`
  - `CITATION`
  - `DISCLAIMER`

### 6.4 Professional PDF (`.pdf`)
- Built using pure-Python `fpdf2` (no external C-runtime or WebKit dependencies).
- Branded deep navy `#0B192C` application header and running footer with dynamic page numbering (`Page X of Y`) and confidentiality notices.
- Executive Summary card with slate borders and distinct typography.
- Color-coded catalyst indicators (`+ Catalyst` in green `#166534`, `- Risk` in red `#991B1B`).
- Structured tabular citation index with article IDs, publishers, dates, and claims.
- Red-tinted regulatory and compliance warning box at the end of each report.
- Latin-1 string sanitization to prevent unicode encoding crashes in standard PDF Helvetica fonts.
- Strict `new_x=XPos.LMARGIN, new_y=YPos.NEXT` positioning to avoid margin wrap-around defects.

## 8. Known Limitations & Operational Considerations

1. **Local SQLite Concurrency:** SQLite WAL mode handles multi-user read concurrency well. However, in enterprise deployments with thousands of concurrent writers, migration to PostgreSQL is recommended.
2. **Font Encoding:** Default PDF fonts in `fpdf2` use the Latin-1 character set. Exotic unicode symbols (e.g., Asian ideograms or non-Latin alphabets) are automatically replaced with standard placeholders (`?`). A TTF Unicode font can be registered if full international multilingual script support is required.
3. **Report Deletion:** Saved reports are retained indefinitely by default. A GDPR/compliance data retention and user deletion policy should be defined in Phase 4.
